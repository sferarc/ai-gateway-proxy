# Proxy

`createGatewayProxy(options)` in `src/proxy.ts` returns a handler `(request, context?) => Promise<Response>` with `GET`, `POST`, `PUT`, `DELETE` and `PATCH` properties that point at the same function, so a Next.js route can export them directly (`README.md`).

## Request path

1. Authenticate with [[auth]]. No credential returns `500 AI Gateway authentication not configured`.
2. Resolve the upstream path. `extractPath(request)` wins when given; otherwise the catch-all route param named by `segmentsParam` (default `segments`) is joined with `/`; otherwise the path is empty. `extractPath` and `segmentsParam` came in 8b8c5ca so Hono, Express and similar frameworks work without catch-all routes (`CHANGELOG.md` 0.1.0).
3. Build the upstream URL as `baseUrl/path` plus the incoming query string. `baseUrl` defaults to `https://ai-gateway.vercel.sh/v1/ai`. Since #10, `isSafePath` and `buildUpstreamUrl` reject a path that starts with `/`, contains `://`, or has a segment that decodes to `.` or `..` or contains `/`, `\` or NUL, so percent-encoded forms such as `%2e%2e` and `a%2F..` are caught too, as is a segment that fails to decode. The resolved URL must also keep the `baseUrl` origin and path prefix. Any of these returns `400 Invalid path` before any `fetch` (the `returns 400 without calling fetch` tests under `request handling` in `src/proxy.test.ts`).
4. A `GET` or `HEAD` request, such as `@ai-sdk/gateway`'s `getAvailableModels()` reading `GET {baseURL}/config`, stops here and goes through `forwardBodylessRequest`: it is sent upstream with no body and only the caller's `headers` with `authorization`, `ai-gateway-auth-method` and `ai-gateway-protocol-version`, and the upstream status and body come back unchanged with the upstream `content-type`. None of the hooks run, since they are typed for `LanguageModelV3CallOptions`, and that includes `onError` on a non-OK status. A thrown fetch returns 500, or 499 when the client aborted. Before this, every `GET` returned `400 Invalid JSON body` (tests under `bodyless requests` in `src/proxy.test.ts`, including one that drives `createGatewayProvider({ fetch })` into the handler).
5. Parse the body as JSON (`LanguageModelV3CallOptions`). Invalid JSON returns 400.
6. Run `beforeRequest`, which may replace the body.
7. `fetch` upstream with the request's method, the re-serialised body and the headers from `buildRequestHeaders`: the caller's `headers`, overwritten by `content-type: application/json`, `authorization: Bearer`, `ai-gateway-auth-method`, `ai-gateway-protocol-version` (`0.0.1`), `ai-language-model-id` and `ai-language-model-streaming`, the last two copied from the incoming request. Both header paths go through `withGatewayHeaders`, which sets these on a `Headers` built from the caller's `headers`, so a custom header in any casing (`Authorization`, `Content-Type`) is replaced rather than sent alongside; a plain object spread kept both keys and `fetch` joined them as `Bearer user, Bearer gateway` (`keeps gateway headers authoritative over custom headers in any casing` and its `on GET` twin in `src/proxy.test.ts`). Header names in the forwarded record are lowercase. The client's `request.signal` is passed to `fetch`, so a client abort cancels the upstream request (#10; `forwards the client signal and returns 499 when the client aborts` in `src/proxy.test.ts`). On a streamed response, cancelling the transformed stream also cancels the upstream body (#11, `cancels the source when the output stream is cancelled` in `src/stream.test.ts`, [[streaming]]).
8. On a non-OK status, parse the error body (falling back to `{ error: { message: statusText, type: "gateway_error" } }`) and pass it to `onError`, which may return a replacement body or a whole `Response`.
9. On success, a streamed request (incoming `ai-language-model-streaming: true`) goes through [[streaming]]; otherwise the JSON body goes through `afterResponse` and is re-serialised.
10. Any thrown error from step 2 onwards returns `500 Error proxying request to AI Gateway`, or 499 with no body when the client has aborted. That includes a throwing `extractPath` or `beforeRequest`, a non-JSON success body and a throwing `afterResponse` or `onError`, which is why the handler `await`s `handleJsonResponse` and `createErrorResponse` inside its `try`: a bare `return promise` lets the rejection escape the `catch` (tests under `error handling` in `src/proxy.test.ts`). A throwing `afterResponse` on a streamed request is logged and the original `finish` event is forwarded unchanged, since the response has already started (`src/stream.ts`, [[streaming]]).

Tests: `src/proxy.test.ts` mocks `fetch` and `@vercel/oidc` and covers each step, the hooks and the HTTP method exports.
