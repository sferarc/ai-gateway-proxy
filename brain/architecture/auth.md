# Authentication

When `createGatewayProxy` gets the `apiKey` option, `resolveApiKeyOption(apiKey, request)` in `src/auth.ts` replaces the chain below: a string, or the result of calling it with the incoming `Request` (awaited), becomes `{ token, authMethod: "api-key" }`. An empty or non-string result logs `AI Gateway auth: the apiKey option gave no key`, and a throw or rejection logs `AI Gateway auth: the apiKey option failed:` with the message only; both return `null`, and the proxy answers 500 `proxy_error` `AI Gateway authentication not configured: the apiKey option gave no key` without calling the gateway or OIDC. It never falls back to the environment, so a tenant without a key is not billed to the operator's credential ([[decisions/2026-11-02-api-key-option-fails-closed]]; "the apiKey option" in `src/proxy.test.ts`). It runs before the body is read, so a function that reads the body would make the proxy's own read fail.

Without the option, `getGatewayAuthToken()` in `src/auth.ts` returns `{ token, authMethod }` or `null`:

1. `AI_GATEWAY_API_KEY` from the environment, as `authMethod: "api-key"`.
2. Otherwise `getVercelOidcToken()` from `@vercel/oidc`, as `authMethod: "oidc"`. This works when deployed on Vercel (`README.md`, "Authentication").
3. Otherwise `null`, and the proxy answers 500 ([[proxy]]). Before returning `null` it writes one `console.error` line, `AI Gateway auth: no AI_GATEWAY_API_KEY and Vercel OIDC token unavailable:` followed by the OIDC error's message (or `String(error)` for a non-Error). Only the message is logged, never the error object or any token.

The method is sent upstream as `ai-gateway-auth-method`. The proxy's `authorization` and `ai-gateway-auth-method` always win over the caller's `headers`, matched case-insensitively, so a custom `Authorization` cannot replace or be appended to the gateway credential ([[proxy]] step 7; `keeps gateway headers authoritative over custom headers in any casing` in `src/proxy.test.ts`). The key is read on every request, not cached. Both branches and the `null` case are tested in `src/proxy.test.ts` ("authentication"); the failure log is tested in `src/auth.test.ts`. Added in 195a421 (monorepo #12).

The proxy does not authenticate its own caller: a route that only calls the handler serves anyone who reaches it. `README.md` ("Protecting the route") shows a handler that checks the client's `authorization` bearer, which `@ai-sdk/gateway` fills from its `apiKey` and the proxy replaces upstream, and answers 401 `invalid_request_error` before calling the proxy; `src/readme-route-auth.test.ts` pins it (#133). The README tells callers not to reject through the `apiKey` option, whose 500 clients retry.
