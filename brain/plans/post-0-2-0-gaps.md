# Gaps after 0.2.0

Open unknowns found by reading [[architecture/proxy]] and [[architecture/streaming]] as of main 50d6250, after #59 to #61, #64 and #66 landed. [[roadmap]] has no open item, so these are the candidates for the next round. Gateway redirects and non-object `afterResponse` results are closed by #64 ([[decisions/2026-10-21-fail-closed-redirects-and-hook-results]]) and are not listed. Each names its source and what blocks it. No item here needs a paid gateway call to write; only item 3 needs one to settle.

1. **Gateway path matching beyond the folded spellings.** Closed: the owner chose the fail-closed alternative in #70 on 2026-10-26. The hooks now run on every path except an exact list of the paths `@ai-sdk/gateway` uses for other calls and job reads, so a spelling the gateway might serve no longer needs to be known ([[decisions/2026-10-26-fail-closed-path-matching]], [[architecture/proxy]] step 6). The gateway's own routing stays unverified, and now only decides whether an unusual spelling of a real non-language-model call breaks a hook typed for language model calls.
2. **Hooks for non-language-model calls.** Embedding, image, video, speech, transcription, reranking, decision and batch start calls run no hook, so an operator cannot meter or audit them through the proxy. Source: step 6 of [[architecture/proxy]]. Blocker: the owner, since per-kind hook types are a public contract change; a first step is a hook that receives the raw request and response for those paths.
3. **Non-language model kinds are untested against the real gateway.** The keyless tests use fakes shaped after `@ai-sdk/gateway` 4.x, and `src/integration.test.ts` calls only `generateText` and `streamText`. Embedding, image, video and batch behavior through the proxy rests on reading the client, not on observed gateway responses. `src/non-language-model.test.ts` pins the proxy side with a fake gateway (path, auth, unchanged body, no hook), which leaves the real gateway's responses unobserved. Source: [[development/testing]]. Blocker: a gateway key and paid calls, which are the owner's ([[decisions/2026-10-08-no-gateway-key-in-ci]]).
4. **Hook results are not validated.** An `afterResponse` result that is an object with missing or wrong-typed fields is serialised as returned, and on a stream the missing fields are left out of the rewritten `finish` event. Arrays and non-objects are rejected, and `undefined` and `null` fall back to the upstream body (see [[decisions/2026-10-21-fail-closed-redirects-and-hook-results]]); the object-field and streaming cases remain. Source: "Hook result without stream metadata" in [[architecture/streaming]] and step 9 of [[architecture/proxy]]. Blocker: the owner, since rejecting such a result instead of forwarding it is a contract choice.
